# 机场接驳班距与排队关联

`hxwl-solo2611-2` · 秩相关与分层分析

各站点在每次发车前清点候车人数，接驳调度交接表提供实际发车班距。值班员导入合并后的发车台账，按线路核对班距与队列的关系，决定哪些线路值得在下一班次试排一辆机动加班车，哪些站点需要先复核客流或上客组织。

## 模拟客户与工作流

模拟客户·云汀机场陆侧交通运行中心，18 名运行值班员与调度员，负责 4 条接驳线路

- 跨线路用一个 Excel 系数，容易把站点客流差异误当成班距影响。
- 班距按整分钟记录，队列人数也常相同，手工排名处理并列口径不一致。
- 排队报警只看单次峰值，交接班缺少统一的补车和补采依据。

陆侧运行值班席将同时达到样本、正相关和排队门槛的线路交给机动运力调度组，下一相似时段试排一辆加班车并复测。队列高但正相关未达门槛的线路先由站坪客运保障组复核到达客流与上客组织。样本不足或系数无定义的线路安排补采；其余线路维持现行班次。

## 业务模块

- 航站接驳台账
- 分层分析设置
- 线路判定图
- 值班发布与收件

## 计算口径

同一线路内比较实际发车班距与本班开始上客前的候车人数。一条线路同一日期和发车分钟只录一条，班距取 1 至 1440 整分钟。台账可覆盖部分采样窗口，实际班距以调度交接表为准。Kendall τ-b 将同序对与逆序对之差除以按单列并列校正的分母，两列同时并列的配对单列记录。任一变量恒定时系数无定义。排队 P90 取升序第 ⌈0.9 × 样本数⌉ 个值。分析用于运营筛查，客流波次、车型容量、临时管制和调度响应均可能影响关联。

样例输入为 `云汀机场接驳发车与队列_2026-11-24.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 24 日 06:00，云汀机场陆侧值班席启动 4 条接驳线路的发车观察。
2. 早高峰期间，各站点在各自采样窗口内逐班记录上客前人数，调度员填写距同线路上次实际发车的整分钟数。
3. 11:10，值班员汇总 48 条记录，导入云汀机场接驳发车与队列_2026-11-24.csv。
4. 11:15，先以每条至少 8 条、τ-b 至少 0.60、候车 P90 至少 25 人运行全部时段。
5. 11:20，切换早高峰复核，S1 的 10 条记录达到试排条件，S4 只有 4 条，交给站点补采。
6. 11:30，值班席发布线路判定，机动运力调度组预排次日早高峰 S1 的一辆加班车。
7. 11:40，站坪客运保障组接收 S2 客流与上客组织复核任务，并准备次日用同口径复测。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18311`，API `http://127.0.0.1:19311`，数据库宿主端口 `17811`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 MySQL 8.0 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
